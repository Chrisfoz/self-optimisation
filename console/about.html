THE IMPROVEMENT LOOP

Fresh ideas enter.
Evidence decides what leaves.

A convincing proposal is only the beginning. Each change must pass the checks you configured.

01 / DISCOVER

Watch the labs you choose

The first check establishes a baseline. Later checks compare model catalogues against that saved snapshot. A manual campaign lets you try a chosen model now.

02 / PROPOSE

Give fresh eyes a clear goal

New models propose changes using your brief and run history. Small, steady improvements by default; after a clean streak, a run may try something bigger. When there are several proposals, the harness ranks them before implementation.

03 / CHALLENGE

Check the actual change

A pinned reviewer examines the result. Rejected edits can be refined within your attempt limit. Protected paths and test failures stop promotion.

04 / DECIDE & LEARN

Merge it, or review it first

A change that passes every gate waits for you as a pull request. Once you're confident in the runs, you can opt in to merging automatically instead. Every outcome is recorded, including when nothing ships, and periodic reviews name open questions you may not have thought to ask. The next model starts with that history.

YOU CHOOSE HOW MUCH TO HAND OVER

Different roles.
One quality bar.

Rotating

The suggester

The newest model from the labs you select proposes the change, so every run benefits from the latest improvements in the field.

Pinned

The implementer

Your chosen model writes or refines edits when needed. It does not get to change the rules.

Pinned

The reviewer

Fresh context and a strict verdict. An unreadable or contradictory approval is rejected.

Deterministic

The gates

The allowlist, diff guard and your existing tests check the work regardless of which model wrote it.

The ranking model can be pinned separately, or selected from another model family when available. Choosing a seat from an unwatched lab still requires that lab’s key.

WHAT TO EXPECT

The harness runs today

The generation loop has been exercised with real model calls and GitHub Actions. The console uses the same configuration and workflow generator as the command-line installer.

Setup depends on your deployment

GitHub sign-in requires a configured GitHub App. You can prepare and download configuration without signing in. API keys are entered on GitHub, never in this console.

It costs real money, so judge it per merged change

Every generation is paid for in API credit, mostly for the models reading the code. On a large web app, a generation that shipped used 393,000 tokens: under $1 for the review, plus the suggesting model's reading. Runs where a pinned model writes the change cost a few dollars more. The fair comparison is the cost of each change that ships, including your review of it, against the time a person would have spent. Runs that spend and ship nothing are the real waste, and the harness now stops the most common ones before paying for them. What it costs

Better models do not guarantee better changes

Your test coverage and project brief still matter. The wider curiosity programme remains partly implemented; it is not a promise of autonomous research.
