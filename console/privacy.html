Implementation notes for this version of the console, 11 September 2026.

Model API keys

The console does not ask you to enter model API keys. Add them directly in your repository’s GitHub Actions secret settings. The console reads secret names to check configuration; it cannot read their values. This check does not establish that a key is valid, funded or entitled to a specific model. The rehearsal makes the actual provider calls.

GitHub sign-in

When the deployment has a configured GitHub App, sign-in exchanges a one-time code for a user access token. The token stays in the server process’s memory and is not sent to browser JavaScript. A secure, HTTP-only cookie identifies your session on HTTPS deployments. Sessions expire within one hour; signing out or restarting the service discards the session.

Repository operations check the App’s current installation access as well as GitHub’s own permissions. The console reads repository metadata, file trees, secret names and workflow results. It writes setup or activation branches and pull requests only when you request them. It can dispatch a rehearsal after setup is merged. It does not merge pull requests.

Your configuration

The browser saves a draft for each project you add, one per repository, in this tab’s session storage so a refresh or GitHub sign-in can resume them. Signing out clears them. The server receives your configuration to validate it and generate files. A connected session retains setup details temporarily for rehearsal status. This implementation does not persist configuration or run history in a database. Remove your projects or sign out when using a shared computer, and do not paste credentials into configuration fields.

Where the work runs

The console does not execute your project’s code or make model calls. Your GitHub Actions workflow runs the harness and sends its configured context to your selected model providers. Test commands execute in that runner. API usage is billed by the providers and Actions usage is subject to your GitHub plan.

Repository configuration, briefs, workflow files and generation records remain in your repository. The console shows workflow status from GitHub; a successful workflow conclusion alone does not mean that a change shipped.

Removing access

Sign out to discard the console session. In GitHub’s Settings → Applications, revoke the App’s authorisation or remove its installation. Disable the self-improvement workflow separately if you want scheduled runs to stop: removing console access does not remove files or disable an installed workflow. Delete repository secrets through GitHub if you no longer need them.

Hosting

The operator of a deployment controls its server and hosting logs. Hosting providers may process request metadata such as IP addresses and timestamps. This application does not log request bodies, tokens or model keys. It uses no analytics scripts or third-party font services. Review your host’s logging settings before operating a public instance.
