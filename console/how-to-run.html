Self-Optimisation · How to run

Download it, run it on your own computer, make it yours.

This project is meant to be downloaded from GitHub and run locally. There's no sign-up and nothing to pay for to look around. Follow the steps in order, copy each command exactly, and you'll have it running in about ten minutes.

What you're downloading

The repository has two halves. You can run the first on its own, and each half is set up in one obvious place, so you can change either without touching the other.

Frontendconsole/

The website

The pages you're reading now, served by one small file, console/server.mjs. It needs no database and no accounts. The shared menu and footer each live in their own file in console/partials/.

Backendharness/

The harness

The part that does the real work. When a new AI model comes out, it asks that model to suggest one improvement to your project, checks the change, and hands it to you. You set it up with one file, project-adapter.yml, and put your keys in another, .env.

Be clear about what's real. The website runs, but the console page on it is a clickable sketch that doesn't save anything yet. To make the harness actually improve a project today, use the commands in Part 2.

Before you start

Install these first. Each one is free.

  • Node.js 22.11 or newer. Go to nodejs.org and download the version labelled LTS. Use the default options in the installer.
  • A code editor with a built-in terminal. For example VS Code or Cursor. If you use an AI coding assistant, open this project in it.
  • Git, from git-scm.com. This is optional: you can download a ZIP instead (Step 1 shows both).
  • For Part 2 only: an API key from at least one AI lab. Anthropic or OpenAI is a good first choice. You don't need one to run the website.

Part 1 — Run the website

About five minutes. At the end, this site will be running on your own computer.

  1. Download the project

    With Git: open a terminal and paste this:

    git clone https://github.com/Chrisfoz/self-optimisation.git

    Without Git: open the repository on GitHub, click the green Code button, choose Download ZIP, and unzip it somewhere you'll find it again, such as your Documents folder.

  2. Open the folder in your editor

    In VS Code or Cursor, choose File → Open Folder… and pick the self-optimisation folder. Then open a terminal with Terminal → New Terminal. That terminal is already inside the right folder, and every command below goes there.

    To check you're in the right place, the folder should contain package.json, README.md, console and harness.

  3. Check Node is installed

    node --version

    You should see v22.11.0 or a higher number. If you see "not recognized" or "command not found", install Node (see Before you start), then close your editor completely and reopen it.

  4. Install the one dependency

    npm install

    This downloads one small library, js-yaml, which the harness uses to read its settings file. The website doesn't need it, but Part 2 does, so it's worth doing now.

  5. Start the website

    npm start

    You should see a line like console listening on :3000. Leave this terminal open, because closing it stops the site.

  6. Open it in your browser

    http://localhost:3000

    Paste that into your browser's address bar. You'll see this site. When you're done, click in the terminal and press Ctrl + C to stop it.

  7. Optional: run the checks

    npm test

    This runs the project's own tests. They should all pass. If you change something and a test fails, the output tells you what broke.

That's Part 1. The website is running locally. Next, you can change how it looks (see Make it yours) or point the harness at a real project (Part 2).

Part 2 — Run the harness on your own project

The harness doesn't improve this repository. You copy it into another project of yours, and it improves that one. Try it on a project you don't mind experimenting with. It works on a separate branch and never changes your main code without you approving it.

This part uses real API credits. Every suggestion is a real call to an AI lab, billed to your key. Set a monthly spending limit on your lab's billing page before you start.

  1. Make sure your project uses Git

    The harness puts each attempt on its own Git branch, so your project must be a Git repository. If it isn't yet, run this in your project's folder:

    git init

  2. Copy the harness folder into your project

    The simplest way is to drag the harness folder from the download into your project's top-level folder in your file explorer. Or, from a terminal inside your project:

    Mac / Linux
    cp -r ../self-optimisation/harness ./harness
    Windows PowerShell
    Copy-Item -Recurse ..\self-optimisation\harness .\harness

    These commands assume both folders sit side by side. Change ../self-optimisation if you put the download somewhere else.

  3. Give your project the settings reader

    In a terminal inside your project, run:

    npm install --no-save js-yaml@5.3.0

    This installs the same library as Part 1, into your project, without changing its package.json. Make sure your project's .gitignore includes node_modules/.

  4. Add your API key

    Copy the example keys file to your project's top-level folder:

    Mac / Linux
    cp harness/.env.example .env
    Windows PowerShell
    Copy-Item harness\.env.example .env

    Open .env and paste your key after the matching name, for example ANTHROPIC_API_KEY=sk-ant-…. Leave the other lines blank.

    Never commit .env. Add a line saying .env to your project's .gitignore now. Anyone who sees your key can spend your money.

  5. Answer the setup questions

    node harness/cli/init.mjs

    It asks about your project: which AI labs to use, which files may be changed, and how to run your tests. Pressing Enter accepts the suggested answer. It then writes:

    • project-adapter.yml, all of the backend's settings in one file
    • .claude/agents/improve.md, where you describe what "better" means for your project
    • .claude/agents/review.md, which tells the reviewer what to check
    • .github/workflows/self-improve.yml, for running it on GitHub later
    • SELF-IMPROVE-README.md, a summary of what was just installed

  6. Fill in the two brief files

    Open .claude/agents/improve.md and review.md and replace every [bracketed placeholder] with real answers about your project. This is the most important step. The AI only knows what "better" means for your project if you tell it here.

    Your AI assistant can draft this. There's a ready-made prompt in Ask your AI assistant below, but read what it writes before you keep it.

  7. Check your settings

    node harness/scripts/validate.mjs

    This catches mistakes before they cost anything, like a file path that doesn't exist or a placeholder you forgot to fill in. Fix what it lists and run it again until it passes.

  8. Do a practice run

    node --env-file=.env harness/scripts/rehearse.mjs

    This runs the whole loop on your computer, on a new local branch. Normally it waits for a newly released model, so on the first run it usually finds nothing, spends nothing and stops. That's expected. To try it right away with a model you choose:

    node --env-file=.env harness/scripts/rehearse.mjs --models claude-opus-5

    It never pushes, opens a pull request or merges. You end up with a local branch you can look at, keep or delete.

  9. Optional: run it on GitHub automatically

    When a practice run looks good, the generated workflow can run the same loop on GitHub every month. That needs your keys added as GitHub secrets and one repository setting turned on. The steps are in the README, under Getting started, Steps 5–7.

If something goes wrong

"node" or "npm" is not recognized / command not found

Node isn't installed, or your terminal was opened before you installed it. Install the LTS version from nodejs.org, then quit your editor completely and open it again.

Windows: "running scripts is disabled on this system"

PowerShell is blocking npm. Run this once, then try again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Or switch your editor's terminal to Command Prompt or Git Bash.

"EADDRINUSE" when running npm start

Something else is already using port 3000, possibly an earlier copy of this site you didn't stop. Close that terminal, or start on another port as shown in Make it yours.

"Cannot find package 'js-yaml'"

Run npm install in this repository (Part 1, Step 4). If the error comes from your own project, run the command from Part 2, Step 3 there.

The page says "Not found"

The server only serves pages listed in PAGES in console/server.mjs, so a new page needs a line there. After any change to the website's files, stop the server with Ctrl + C and run npm start again, because pages are loaded once at startup.

npm test fails straight away with "Could not find" or a strange file name

Your Node version is probably too old. Run node --version, and if it's below 22.11, install the current LTS.

The practice run says "no new models" and stops

That's expected. The first time it sees a lab, it records that lab's current models and waits for a new one. Add --models claude-opus-5 (or another model your key can use) to try one straight away.
